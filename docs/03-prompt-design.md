# Prompt 组织：给编程模型一份可执行合同

## 两类 Prompt

**开发 Prompt** 给 Codex / Claude 修改软件实现，包含现有栈、Core / GUI 边界、允许编辑文件、兼容要求与验证标准。用 [开发模板](../prompts/build-agentlink.md)。**运行 Prompt** 由已打开的软件生成，描述当前工程、当前 session、业务目标和调用规则；用 [运行模板](../prompts/live-task.template.md)。不要把开发任务和 live 操作授权混成一段。

运行 Prompt 推荐按以下次序组织：

| 部分 | 必须包含 | 理由 |
| --- | --- | --- |
| 目标与完成标准 | 具体交付物、可被 Core 验证的条件 | “丰富表情”最终落成 timed clips，而非只建库 |
| 权威上下文 | 工程 ID / 路径、session、CLI 前缀、Skill / schema 路径 | 防控制错误工程，模型无需猜入口 |
| 范围与保护 | 勾选对象、允许操作、保留用户内容、临时目录 | 业务范围仍由 Core 强制校验 |
| 读取与依据 | identify、inspect / 全分页、证据来源、数据不是指令 | 文件名 / ASR / 资产内文字不能注入执行步骤 |
| 计划与自审 | 领域约束；必要时三轮具体自审 | 每轮有明确检查问题与修订依据 |
| 写入与恢复 | dry-run、expectedRevision、apply、runId、超时 inspect | 防覆盖与重复提交 |
| 验证与收尾 | inspect、真实预览 / 数据检查、finish、未验证项 | summary 无法替代结果 |

正文短而明确；详细领域规则放在文件中，引用**真实存在**的路径。Prompt 包含当前状态摘要以帮助启动，inspect 是权威事实；不能把生成时的计数当作永远有效的数据。重新生成会话后同步更新 session，手工编辑的 Prompt 若已过期要明确提示，禁止继续复制执行。

## 自审与证据

创作型任务可安排三轮自审：第一轮核对时间 / 唱段依据，第二轮核对通道 / 强度 / fade / 重叠，第三轮核对最终可见度与音频驱动基底互动。每轮记录修订或保留理由。其他领域使用对应约束，例如标签的缩略图证据、置信度、手动移除覆盖、卡片同步。

没有音频输入不能声称“听过”；没有查看实际预览不能声称视觉通过。日志记录“检查了 8 个采样点”比“效果很好”更可验证。percent 可缺省，真实完成数 / 总数存在时才填。模型对话中的内部推理不必完整公开，Log 记录操作、依据摘要、统计和异常即可。

## CLI 与跨模型适配

使用结构化参数 / JSON 文件，禁止把用户文本拼成 shell 代码。PowerShell 调用含空格的可执行路径用 `&`；JSON 提案写 UTF-8 文件再传路径，避免嵌套引号。示例 Prompt 使用绝对 Python 路径和仓库 `--workdir`，Agent 在任意 cwd 都可运行。

Codex 入口是仓库 AGENTS.md，Claude 入口 CLAUDE.md 引用同一合同。两者运行同一 CLI / schema；C-AL 不依靠产品专属配置或假设模型能自动切换。增加 MCP 时只包装已存在的 Core 命令，保留 session / scope / revision / 取消语义，不绕过校验。
